# P0-5 Record Flow 视觉验收

## 目标与范围

验收“地点详情 → 城市碎片编辑 → 时间轴/相册 → 城市碎片详情 → 地点回顾”的产品视觉与交互。测试数据必须来自当前本地 Repository 和真实系统相册，不使用假照片或假记录。本清单不把尚未实现的缩略图、相机、地图或平板双栏视为已完成。

## 1. 构建门禁

在仓库根目录执行：

```powershell
./gradlew :shared:testDebugUnitTest :androidApp:testDebugUnitTest --no-daemon
./gradlew :androidApp:assembleDebug --no-daemon
./gradlew -c settings.ohos.gradle.kts :shared:compileKotlinOhosArm64 --no-daemon
```

配置了 `OHOS_SDK_HOME` 或 `DEVECO_STUDIO_HOME` 的环境还需完成 HarmonyOS native link、ArkTS 测试和 signed HAP 构建。任何失败都不得用旧 APK/HAP 代替当前源码验收。

## 2. 测试数据准备

- 至少建立跨两个本地年月的 4 条已发布城市碎片。
- 同时包含：无照片、1 张照片、多张照片、无心情、含心情、长正文、长地点名、地点已缺失的降级数据。
- Gallery 压力验收准备至少 20 张、最好超过 36 张真实照片，以覆盖 18 张一批的“继续查看”。
- 分别在 Light/Dark、默认字体/系统大字体下执行核心页面检查。

## 3. Editor 验收

1. 从地点详情点击“在这里留下城市碎片”，确认二级编辑页没有 Bottom Navigation。
2. 顶栏只出现关闭与“完成”；页面底部没有第二个发布/保存主按钮。
3. 确认照片、自然正文输入、心情 chips、只读地点行、标签依次形成阅读层级，没有每组套 Card。
4. 不修改内容直接关闭：应直接返回，不弹草稿选择。
5. 修改正文或照片后关闭：Bottom Sheet 必须按“保存草稿并退出 / 继续编辑 / 放弃修改”提供三条明确路径。
6. 选择“继续编辑”：保留全部输入并回到编辑器。
7. 选择“保存草稿并退出”：返回上一页；从同一地点再次进入时恢复正文、照片、心情和标签。
8. 选择“放弃修改”：返回且不恢复本次修改；本次新复制且无其他引用的托管照片应被清理。
9. 点击“完成”：只发布一次并 replace 到对应 Capsule Detail；快速重复点击不得产生重复记录。
10. 系统相册取消、失败、超出 9 张、单图移除均不丢失已有正文或其他照片。

## 4. Timeline 验收

1. 打开“记录”，默认显示时间轴，外层只存在一个 Bottom Navigation。
2. 月份按设备本地年月分组，组内保持 catalog 的时间倒序；跨月边界不得按 UTC 错分。
3. 每条记录显示大日期、地点、可用照片和正文摘录；无照片时布局仍完整。
4. 月份与日期不套 Card，记录不呈现连续的大面积通用 Card 或“查看/编辑/删除”按钮堆叠。
5. 点击整条记录进入 Capsule Detail；返回后仍在 Record 根页且保留合理的列表位置。
6. 长列表连续滚动时无整页 Loading、明显错图、重复项或无稳定 key 导致的跳动。
7. 空 catalog 显示“留下第一条碎片/去探索地点”一类产品动作，不出现 Repository、MMKV、路由或“已接入”等说明。

## 5. Gallery 验收

1. 在 Record 内点击“相册”，不得 push 新页面或增加第二个底栏。
2. 图片按设备本地年月分组；手机为 3 列，较宽窗口为 4 列，照片单元没有 Card 和文字按钮。
3. 首批最多组合 18 张照片；超过时显示“继续查看”，每次增加下一批，20/36+ 张数据不会首屏一次加载全部原图。
4. 点击任意照片进入其所属 Capsule Detail，返回后仍位于相册视图。
5. 单张路径失效只显示该格 fallback，不阻断其他月份和照片。
6. 当前没有缩略图能力：验收通过只表示批次保护有效，不代表内存和解码优化已经完成。

## 6. Capsule Detail 与回忆闭环

1. 从 Timeline 或 Gallery 打开详情：照片优先，随后是本地日期/心情、正文、标签和地点。
2. 多图时首图为主视觉，其余图片进入自适应网格；无图时不伪造摄影素材。
   - 2 张照片必须同一行等宽、等高展示；3、5 张照片的主图后续行必须均衡填满，不出现孤立在左侧、右下角大面积空缺的固定三列尾行。
3. 页面正文区域不显示常驻“编辑/删除”按钮；两项操作只从右上角更多菜单进入。
4. 编辑后完成回到同一详情，内容与照片更新；返回 Record 后 Timeline/Gallery 能读取更新结果。
   - 从 1 张照片开始，连续执行三次“编辑 → 添加 1 张 → 完成”，每次完成只关闭当前 Editor 并刷新原详情；随后一次返回应直接离开详情，不能依次看到 4/3/2/1 张照片的四个历史详情页。
5. 删除必须二次确认；取消不改变数据，确认后回到 Record 根且该记录从 Timeline/Gallery 消失。
6. 点击地点整行进入真实 Place Detail；关联地点不存在时显示诚实降级文案且不可假跳转。

## 7. 双端与失败状态

- Android 与 HarmonyOS 分别完成真实系统相册成功、取消、失败恢复、应用重启后读取。
- 检查状态栏/安全区、返回键/返回手势、Bottom Sheet 点击遮罩、更多菜单关闭和二级页无底栏。
- 检查中英文长文本、长地点名、大字体、Light/Dark 下的截断、对比度和触控目标。
- Editor 分别添加、删除首张/中间/末张照片：未变化照片不得闪白、错图或重新抖动；删除控件保持至少 48dp 触控区，但可见圆形按钮统一为 32dp，Android/HarmonyOS 视觉大小一致。
  - 特别观察删除后跨越原行边界的第一张照片：它只能移动和重新裁切，不能短暂出现白块或重新加载占位。
  - 叉号必须在圆形按钮的几何中心；两端不得因字体基线不同而向下偏移。
- 删除记录、移除照片、放弃草稿后，按 `P0_RECORD_FLOW_ACCEPTANCE.md` 继续验证托管媒体引用保护与清理。

## 通过标准

- 四个页面的内容层级、唯一 Primary 与管理动作位置符合本清单。
- “保存草稿并退出 / 继续编辑 / 放弃修改”三条退出路径结果正确且不丢数据。
- Timeline/Gallery 的本地年月分组、稳定顺序、返回状态和 18 张批次保护正确。
- 自动化与当前源码构建通过；双端真机没有阻断主流程的崩溃、错图、返回栈或安全区问题。
- 未实现能力仍以缺口记录，不通过文案或静态 UI 伪装为已完成。
