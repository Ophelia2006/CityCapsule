# 漫游回顾双端验收

## 自动化基线

- `:shared:testDebugUnitTest`：报告派生、协议迁移与既有回归通过。
- `:androidApp:compileDebugKotlin`：Android 地图双折线、本地时间和分享 bridge 通过编译。
- HarmonyOS `assembleHap`：ArkTS 地图双折线、本地时间、Share Kit 与 signed debug HAP 通过构建。

## 新记录主路径

1. 新建包含 3 个当前城市地点的路线，调用真实步行规划后保存；其中两个地点预先加入“想去”。
   另做一次“不点右上角保存、规划完成后直接开始漫游”的路径，结束后也必须存在灰色规划线，以验证开始前自动持久化。
2. 开始按路线漫游并产生有效 GPS 轨迹；到达一个想去地点和一个非路线附近地点，跳过一个计划地点。
   使用一条从未手动规划过的旧路线直接点击开始：应自动显示“正在自动生成真实步行路线”，成功后直接进入会话，不出现确认弹窗。
3. 在两次到达后分别创建碎片：第一条含照片、平静心情、文字和标签；第二条含惊喜心情、文字和另一标签。
4. 结束并打开回顾。封面应为第一张真实照片；开始/结束为设备本地时间；时长和距离正确；灰色计划道路与琥珀实际轨迹同时存在；想去完成数、非路线发现数、绕路和跳过数符合事实。
5. 沿途时间轴按发生顺序显示“到达 → 对应照片/心情/文字”，心情为“平静 → 惊喜”，标签只来自本次碎片。
6. 点击分享：Android 出现系统 chooser，HarmonyOS 出现 Share Kit 面板；分享摘要逐项与回顾一致。

## 降级与回归

- 无照片：不显示假封面，轨迹地图成为主要视觉；无轨迹：仍显示事实摘要和时间轴。
- 只采到 0～1 个有效 GPS 点：只显示灰色计划线并明确提示实际轨迹点不足；不得将灰线标成实际路线。正常步行并采到至少 2 点后必须出现琥珀线。
- 路线会话内“下一站”按未打卡顺序自动变化；若下一站存在旧碎片，最多展示两条且可进入详情，没有旧碎片时不显示假回忆。
- 开始路线漫游后无需滚动，应自动弹出下一站 Bottom Sheet；完成当前地点打卡后自动弹出新的下一站。同一地点关闭弹层后不得循环弹出；首次地图隐私确认与下一站弹层不得同时叠加。
- v1 旧打卡：“完成想去”显示“旧记录未采集”；v1 旧路线不显示计划线、绕路或跳过详情。
- 拒绝地图同意：页面其他内容可读；同意一次后其他地图页复用应用级状态。
- 分享取消/无目标应用不得修改回顾或崩溃。
- 杀进程重进后，history、计划快照、实际轨迹和关联碎片仍可恢复。
