# CityCapsule User Flows（Proposal）

> 已确认的产品流程基线。方括号中的“规划”能力在实现前不得显示为可成功操作。

## Flow 1：发现地点

**动机**：快速找到一个值得了解或稍后去的本地地点。

1. 探索首页：从 seed 与用户自建地点的混合 catalog 中，按可解释的本地规则选出一个重点地点，同时显示分类入口和真实最近记忆；主操作为点击重点地点整卡。
2. 地点详情：看到名称、分类、城市/区域、地址、标签、备注；轻触“想去”切换状态。
3. 成功：按钮状态与本地 favorite 集合一致，返回列表后仍保留。

空状态：首页 catalog 不可用时说明“还没有可探索的地点”，提供“新建地点”；没有摄影资产时显示类别 fallback。失败时保留原状态并提示重试。中断后重新进入详情，从 Repository 重新读取。返回路径为详情 → 原列表/首页。

## Flow 2：实际探索

**动机**：从目录或空间视图找到地点并前往。

1. 探索首页：点击搜索框、分类或“查看全部地点”进入探索列表。
2. 探索列表：默认显示列表并加载各地点对应的真实图片；单图不可用时仅该缩略图回退为类别 fallback。地图 capability 上线并通过双端验收后，顶部才显示“列表 / 地图”切换；该操作只切换同一探索容器的视图状态，不产生页面入栈或出栈。
3. 列表/地图：看到地点名称、分类、区域；只有位置 capability 完成后才显示距离与当前位置。
4. 地点详情：阅读地址与备注。
5. [规划] 外部导航：平台返回成功/取消/失败/不支持；当前阶段不提供假按钮。

当前可交付成功结果仅是“找到并打开地点详情”。地图权限拒绝、SDK 不可用或离线时回到列表；定位失败不阻塞浏览。中断后保留搜索与筛选状态（实现时验收）。返回路径为详情 → 原视图 → 探索首页。

## Flow 3：留下记录

**动机**：在地点上下文中保存一刻。

1. 地点详情：Primary CTA“在这里留下城市碎片”。
2. 编辑器：地点固定显示；选择最多 9 张照片，填写正文，可选心情与标签。
3. 保存：校验后发布，replace 到碎片详情。
4. 成功：碎片进入 catalog，可在时间轴和相册看到；托管图片被引用保护。

空状态：照片可选，正文规则以当前 Validator 为准；没有照片不显示空照片 Card。Picker 取消保持编辑内容；权限拒绝/不支持/复制失败显示可恢复提示。保存失败保留输入。退出时可保存草稿或确认丢弃；同一上下文草稿下次恢复。丢弃、移图或删除触发引用保护清理。返回路径为详情 → 地点或时间轴。

## Flow 4：回顾记忆

**动机**：按时间或照片重访城市经历。

1. 记录 Tab：进入同一个 Record 根容器，默认时间轴，显示日期、地点和碎片摘要；一级底栏持续存在。
2. 切换相册：当前点击 segmented control，只更新 Record 容器的 `RecordRootView`，不执行页面导航；看到由同一 catalog 派生的照片网格，底栏不消失。左右滑动属于 P0-3B。
3. 碎片详情：阅读内容，并通过关联地点返回地点详情。

成功结果是重新定位到记忆与地点。无碎片时提示“还没有留下城市记忆”，操作为“去探索地点”；有碎片但无照片时相册显示语义空态并切回时间轴。地点丢失属于 Partial Data：保留碎片内容，地点显示“地点信息暂不可用”。读取失败提供重试。中断后回到记录 Tab 时重新加载 catalog。

## 跨流程状态约束

- Offline：当前核心数据本地可用；不得显示网络同步状态。若未来接入远端，离线仍优先展示本地数据。
- Permission Denied 只适用于照片选择及未来定位/地图，不应成为纯本地列表的全屏阻断。
- 所有失败都不得模拟成功；所有危险删除都需要确认并保留可理解的结果反馈。
- 底部“探索 / 记录 / 我的”位于单一 AppShell；点击其他 Tab 以 `animateScrollToPage` 切换，重复点击 no-op，根手势暂时关闭。真正进入详情和操作页时才使用 typed 导航栈。
- Record 内部“时间轴 / 相册”当前使用 Compose 状态点击切换，不调用页面 `push`、`replace` 或 `back`；内部 Pager/左右滑动待 P0-3B。
- 地点摄影能力完成前统一使用类别 fallback；Profile 只展示可由现有数据精确计算的碎片数、关联地点数和想去数。
