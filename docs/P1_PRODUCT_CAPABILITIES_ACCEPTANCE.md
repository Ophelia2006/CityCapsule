## P1-1 用户照片头像

Profile schema v2 支持预设或托管文件头像；相册/相机原图经平台能力居中裁切为 256×256 JPEG，保存到 `images/avatar`，MMKV 只保存 `file://` 引用。保存后清理旧头像，丢弃/替换时清理未保存头像；缺文件回退预设头像；备份 v9 收集并重写路径。

验收：

1. 相册选择横图、竖图、大图，以及拍照成功；确认方形裁切且重启仍显示。
2. 覆盖取消、权限拒绝/永久拒绝、相机不可用；失败不得覆盖旧头像。
3. 连续更换后保存与更换后放弃，核对最终引用及旧/临时头像清理。
4. 导出、清除、导入后头像恢复；移走文件后回退预设头像。

## P1-2 路线拖拽排序

编辑态使用 `Reorder(fromIndex,toIndex)`；长按 Drag Handle 后重排并驱动列表滚动，只有点击保存才写 Repository。辅助菜单保留移到顶部、上移、下移、移到底部。

验收：

1. 用至少 8 个地点验证末项到首项、中间到末项及上下边缘持续拖动。
2. 拖动后返回应保持旧顺序；拖动并保存后重启保持新顺序。
3. 用辅助菜单完成相同移动，并检查屏幕朗读和触控区域。

## P1-3 自由漫游

自由漫游使用真实前台定位与轨迹；采样列出 500 米内本地点，200 米内允许 GPS 确认，定位中断时允许手动记录。打卡后进入 `CapsuleEditor(placeId, roamingSessionId)`；Capsule schema v2 显式保存会话 ID，总结不再按时间范围猜测。结束后可按去重后的打卡顺序保存路线。正式一级导航仍不增加“漫游”。

当前 Capsule Detail 会标注“来自一次自由漫游”。现有 Repository 只保存一个当前/最近会话，没有漫游历史目录，因此旧 Timeline 记录尚不能可靠打开对应历史总结；本轮不以错误路由或时间猜测伪装该能力。

验收：

1. 确认轨迹点、附近距离真实变化，500 米外不显示，200 米外不能 GPS 打卡。
2. 覆盖定位拒绝、关闭、超时、中断后手动记录与恢复采样。
3. 从打卡地点创建碎片；总结只统计相同 `roamingSessionId` 的碎片。
4. 保存路线后顺序等于首次打卡顺序；零打卡拒绝保存。
5. 覆盖暂停、继续、杀进程恢复和反复进出；当前仅前台采样，不宣称后台轨迹。

## P1-4 真实搜索、分类与附近

当前代码已具备本地名称、地址、行政区、标签、简介搜索，真实分类和坐标距离；无定位时不伪造距离。高德结果经 `PlaceRemoteDataSource` 返回，仅用户点击后转换为本地 `IMPORTED Place`，按 provider ID 去重；失败保留本地 catalog，不批量持久化结果。

验收：

1. 分别用名称、地址、行政区、标签、简介词命中，并组合分类验证。
2. 允许定位时验证距离；拒绝时仍显示当前城市内容且无虚假距离。
3. 在线结果不保存即重启，确认未入 catalog；单项保存后可离线查看。
4. 重复 provider ID 不重复导入；无 Key、断网、弱网、空结果、服务错误不丢本地状态。
