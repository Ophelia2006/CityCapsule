# CityCapsule UI/UX Audit

> 状态：2026-07-29 文档同步版；本文记录当前事实与已确认方向，不授权自动修改 UI 或业务代码。

## 1. 审计范围与证据

- 已核对 `AGENTS.md`、架构/决策/当前状态/TODO、初始规划基线、Design System、共享路由、页面、StateHolder、Repository 与现有测试。
- 附件目录仅有需求文本，没有页面截图。因此本文能确认代码结构、文案、数据与交互，不能把字体、阴影、系统栏或真机排版判断写成事实。
- 当前真实数据均为本地 MMKV 中的有限结构化数据；照片原图位于应用沙箱。没有网络 POI、地图 SDK、定位、相机、外部导航、AI 推荐、云同步或导入导出闭环。

## 3. 逐页问题报告

### Home

- AppTheme/AppRoute/Replace 等开发信息已经移除，Home 已成为“探索”真实根页并显示正式底栏；不再属于 Debug 页面。
- 当前内容仍只有“探索地点 / 想去”两个大按钮，没有 Place/Capsule/Favorite 数据、搜索、分类、重点地点、最近记忆或业务状态。
- 已确认目标：从 seed 与用户自建地点混合 catalog 中按可解释规则选择重点地点，整张重点地点 Card 是 Primary；摄影能力完成前统一类别 fallback。

### 地点列表 / 想去

- 搜索、筛选、清除、新建、重载、返回集中在同一层级；“找一个地点”与 catalog 管理混杂。
- 当前 PlaceCard 可复用且整卡可点，这是正确方向；但无照片资产，必须继续使用已登记的类别 fallback。
- “附近、距离、地图”均没有数据依据；列表只能诚实表达本地地点目录与想去筛选。
- Favorites 复用列表实现合理，但用户文案必须始终为“想去”。

### 地点详情

- 真实字段完整，但以 Section + 多按钮呈现，地点信息、记录入口、时间轴、想去、编辑、删除、返回几乎同权。
- 最重要的产品动作应为“在这里留下城市碎片”；“想去”是轻量状态动作，不应占用同级大 CTA。
- 编辑/删除属于低频 catalog 管理，应收进溢出菜单；返回应由顶部导航承担。
- 无照片、坐标、距离与导航能力，不能设计成带真实 Hero 摄影或“到达地点”的完成态。

### 地点编辑

- 表单与保存/放弃状态真实，失败会保留输入，基础交互可靠。
- 页面天然是操作页，不应进入一级导航或首页；分类选择不需要每项大按钮。
- 新建 seed 与用户自建地点目前无来源区分，删除规则不可在 UI 中伪造。

### 碎片编辑

- 已有真实地点上下文、选图、移图、心情、标签、正文、草稿、发布、未保存退出确认，是当前最完整主流程。
- “发布/保存到城市记忆”应为唯一 Primary；保存草稿为次级，关闭为导航行为。
- 照片、心情、正文均用 Section 容器，容易产生“每块都是卡片”；表单分组可用留白和分隔线替代外框。
- 权限/取消/不支持/失败已存在能力边界，设计不可用模拟成功覆盖。

### 时间轴 / 相册

- 两者共享真实 catalog，互相切换合理；空态可引导去地点列表，而不是显示空 Card。
- Timeline/Gallery 正式入口已迁入同一个 RecordRootContent，点击切换且底栏持续显示；内部 HorizontalPager/左右滑动尚未实现，独立 Gallery page 只作兼容。
- 时间轴目前只有单列，信息结构可加强“日期 → 地点 → 片段”；相册应让图片成为主视觉，不叠加管理按钮。
- 没有按城市独立索引或统计，不应宣传自动城市足迹。

### 碎片详情

- 回到地点、编辑、删除、查看全部、返回均是按钮，主线被管理动作稀释。
- 内容本身应是主角；关联地点整行可点，编辑/删除进入溢出菜单，返回由顶栏承担。
- 地点缺失时已有降级需求，不能阻断对旧碎片的回忆。

### 本地档案

- 当前是档案查看/编辑页，不是需求语义中的“我的城市档案”：没有真实统计、想去摘要、城市足迹入口聚合。
- 编辑与清除档案并列，危险操作过于突出；清除应下沉到设置中的危险区。
- “后续页面使用的本地身份”等说明偏开发阶段，不帮助用户理解城市记录。
- 已确认首版展示三个真实统计：碎片数、关联地点数、想去数；只可从现有 catalog/repository 精确计算。

### 设置

- 主题选择、即时预览、持久化失败回滚和重看引导真实可用；shared、MMKV、AppNavigator、路由验收、Push 等文案已经移除。
- Router/Image Adapter 诊断代码仍存在，但正式产品 UI 不可达；应继续保持隔离。
- 数据管理/导入导出尚未完成，只能标注规划，不得提供假入口。

## 4. 可复用与需治理组件

可复用：语义 token、`AppScaffold`、TopBar、BottomNavigation、SearchField、两种 PlaceCard、两种 CapsuleCard、PhotoGrid、状态组件、Icon、ConfirmDialog、BottomSheet、Overflow Menu。

需治理：减少 `AppCard/AppSection` 的泛用；按钮层级按每页一个 Primary 收敛；AppIcon 需双端字形验收；Elevation 需真机验收；正式页清除技术文案；大窗口 AdaptivePane 尚未实现。

## 5. 结论

P0-3A 单一 AppShell 已完成代码与自动化验证，后续重构应保留唯一底栏、无手势根 Pager和 Record Flow 的真实状态机。下一步先验收 AppShell 设备体验并完成 Record 内部 Pager，再按单 Feature 推进 Home 与地点详情。地图、导航和真实摄影必须在 capability/授权/迁移完成前保持隐藏或类别 fallback，不能用静态图冒充。
